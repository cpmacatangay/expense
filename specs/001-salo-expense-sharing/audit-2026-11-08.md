**Fixed and verified**

- History now reads receipts, items, and coverage in three queries (was 6 × N) and renders as a
  `LazyColumn` of cards; verified with real data.
- Ledger payment history is virtualized the same way: header, balances, transfers, and one card per
  settlement, verified by recording a ₱50 payment on device.
- Every interface string — screens, navigation, dialogs, and view-model messages — now comes from
  `strings.xml` (248 strings, 9 plural families, 197 call sites). The shareable recap keeps its
  literal copy as a generated document, and backend diagnostics that embed server responses stay
  verbatim.
- The primary action moved from a floating button into the Home statement card. At `font_scale 1.3`
  the FAB had covered the "View all" control and the last outing row; nothing overlaps now.
- The profile switcher announces "Switch profile. Current profile CP." and its touch bounds measure
  71 × 48 dp.
- Settings' profile label now tracks real state: `BACKED UP` while the block below reads
  "Backed up", `BACKUP ERROR` in error color when a sync fails.
- Plurals render correctly: "1 recent outing", "1 outing · 0 student meals", "1 meal".
- Peso formatting is pinned to `en-PH`; the ledger, recap, and CSV cannot drift with device locale.
- Signing out moved from the profile card into the Private backup block, so the email no longer
  breaks mid-domain at `font_scale 1.3`.

**New P0 found during verification, fixed**

- **Backups died an hour after sign-in.** The stored Supabase access token expired and nothing
  refreshed it; the worker then failed every retry with `PGRST303: JWT expired`, and the UI kept
  claiming a signed-in session. The app now persists the refresh token and expiry, refreshes before
  a request (and once more on a 401), saves the rotated token, and clears the session with
  "Your session expired. Sign in with Google again." when refresh is impossible. Verified by forcing
  an expired session, watching the refresh succeed, then confirming a normal backup still works with
  the rotated token.

**Still open**

- Landscape is functional but a stretched phone column; no size-class layout (P3, out of scope while
  the product targets one phone).
- No TalkBack pass (P3).

## Platform Conformance Verdict

**Pass.** This reads as a native Android app, not a port.

- Material 3 `Scaffold`, `TopAppBar`, `NavigationBar` (five destinations), `ExtendedFloatingActionButton`,
  `AlertDialog`, `SnackbarHost`, `OutlinedTextField`, `FilterChip`, `HorizontalDivider`.
- System Back is not intercepted anywhere (no `BackHandler`); target SDK 37 means predictive back is
  on by default and Compose Navigation participates.
- Edge-to-edge via `enableEdgeToEdge()` with Scaffold insets applied to the `NavHost`.
- Icon set is uniformly `Icons.Filled` (Material), no mixed families.
- No iOS idioms: no segmented control, no Cupertino dialogs, no bottom-sheet-only navigation.

Violations found: the FAB overlapping content, and the sub-48 dp profile switcher. Both are listed
below.

## Executive Summary

- Audit Health Score: **15/20 (Good)**
- Total issues: **11** — P1 × 2, P2 × 5, P3 × 4
- Cold start measured on hardware: **416 ms**
- Top issues:
  1. History recomputes all outing details on every emission (N+1 queries) and renders them in a
     non-lazy column.
  2. The profile switcher's clickable row is 32 dp tall.
  3. The Home FAB covers the right half of the last recent-outing row.
  4. Settings tells two different truths at once: "LOCAL LEDGER" while backup status says "Backed up".
  5. All 121 user-facing strings are inline Kotlin literals; zero `stringResource` usage.

## Detailed Findings by Severity

### [P1] Profile switcher is below the 48 dp touch target

- **Location**: `app/src/main/java/ph/salo/app/ui/SaloApp.kt:127-140`
- **Category**: Accessibility
- **Impact**: The only way to change adult profile at the table is a 32 dp row inside the top app
  bar. One-handed misses land on the app bar instead, and TalkBack's hit area is equally small.
- **Guideline**: Material — 48×48 dp minimum touch target, 8 dp separation.
- **Recommendation**: Wrap the row in `Modifier.heightIn(min = 48.dp)` and add horizontal padding
  so the avatar plus name still look centered. Add `semantics { role = Role.Button; contentDescription = "Switch profile, currently <name>" }`.
- **Suggested command**: `/impeccable polish`

### [P1] History is an N+1 query plus an unbounded, non-lazy list

- **Location**: `feature/history/HistoryViewModel.kt:69`, `feature/history/HistoryScreen.kt:76`
- **Category**: Performance
- **Impact**: Every emission of the range/outings flows re-reads six tables per outing
  (`getDetails` × N) inside a `combine` transform, then `HistoryScreen` renders every outing, every
  student row, and the totals inside a single `verticalScroll` column. With a year of outings this
  becomes hundreds of queries and a fully composed list on each change — visible jank and a slow
  tab switch on the device.
- **Guideline**: Virtualize long lists (`LazyColumn`); avoid per-row suspension in flow transforms.
- **Recommendation**: Build one aggregate query (or a `@Transaction` DAO method) that returns
  outings + shares + student coverage for the range, and render the outings and per-student sections
  as `LazyColumn` items. Keep the totals as a sticky/prepended item.
- **Suggested command**: `/impeccable optimize`

### [P2] Home FAB overlaps the last recent-outing row

- **Location**: `ui/SaloApp.kt:190-197` (FAB), `feature/home/HomeScreen.kt:60-70` (scroll column padding)
- **Category**: Layout / Platform Conformance
- **Impact**: On the captured Home screen the extended FAB covers the right side of the "Test Meal"
  row, hiding the chevron and stealing taps intended for the row. A row can become untappable when
  it is the last item.
- **Guideline**: Material — a FAB must not obscure content or another action.
- **Recommendation**: Add `contentPadding = PaddingValues(bottom = 88.dp)` to the Home scroll
  container (or `Spacer(Modifier.height(88.dp))` after the last card) so content clears the FAB.
- **Suggested command**: `/impeccable layout`

### [P2] Ledger payment history is rendered without virtualization

- **Location**: `feature/ledger/LedgerScreen.kt:173-215`
- **Category**: Performance
- **Impact**: `settlements.forEach` composes every payment ever recorded inside the screen's scroll
  column, each with an `IconButton`. Over time this is the second-longest list in the app and the
  most expensive per row.
- **Recommendation**: Move the payment history into the existing `LazyColumn` pattern or cap the
  visible history with a "View all" route. Do not nest a lazy list inside the current scroll column.
- **Suggested command**: `/impeccable optimize`

### [P2] Conflicting backup state on the Settings profile card

- **Location**: `feature/settings/SettingsScreen.kt:121` vs `:196-206`
- **Category**: Appearance / Clarify
- **Impact**: The card under the profile permanently reads "LOCAL LEDGER" while the backup block
  below can read "Backed up" and "Signed in as …". Two opposite states on one screen undermine the
  privacy guarantee the section exists to communicate.
- **Recommendation**: Drive that label from `backupState.status` and the session: `LOCAL LEDGER`,
  `BACKED UP`, `SIGNED OUT`, or `BACKUP ERROR`.
- **Suggested command**: `/impeccable clarify`

### [P2] All user-facing copy is inline; no string resources

- **Location**: 121 literals across `feature/**` and `ui/**`; `res/values/strings.xml` contains only
  `app_name`; zero `stringResource` calls.
- **Category**: Appearance / Hardening
- **Impact**: Copy changes require code edits, the app cannot be localized for a Filipino household,
  and TalkBack output cannot be tuned per locale. It also makes the plural bugs below permanent.
- **Recommendation**: Move user-facing strings into `strings.xml` with `plurals` for the count
  strings, and reference them via `stringResource`. Keep enum/database values as code.
- **Suggested command**: `/impeccable harden`

### [P2] Light theme, landscape, and large font scale are unverified

- **Location**: verification process
- **Category**: Adaptivity
- **Impact**: Dark portrait at default scale is the only configuration with device evidence. The
  light scheme exists and passes static contrast checks, but the status bar icon mode, the light
  surface steps, and any clipped label at `font_scale 1.3` have not been seen. Landscape rotation
  recreates the activity and squeezes the fixed wizard footer.
- **Recommendation**: Before release, capture Home, Ledger, and the wizard at: light theme, dark
  theme, `font_scale 1.3`, and landscape. Restore `font_scale` and `user_rotation` after.
- **Suggested command**: `/impeccable adapt`

### [P3] Pluralization: "1 recent outings", "1 meals"

- **Location**: `feature/home/HomeScreen.kt:103`, `feature/history/HistoryScreen.kt:139` and `:200`
- **Category**: Copy
- **Impact**: A one-outing ledger — the state most users see in week one — reads as a bug.
- **Recommendation**: Use `pluralStringResource(R.plurals.recent_outing, n, n)` and equivalents.
- **Suggested command**: `/impeccable clarify`

### [P3] Archive confirmation is not styled as destructive

- **Location**: `feature/students/StudentsScreen.kt` (archive `AlertDialog` confirm button)
- **Category**: Consistency
- **Impact**: Voiding a payment and deleting an outing use the error-colored confirm from
  `ConfirmDialog`; archiving a student does not, even though it removes them from every future
  roster pick.
- **Recommendation**: Reuse `ConfirmDialog(destructive = true)` for archive.
- **Suggested command**: `/impeccable polish`

### [P3] Balance card is announced as three separate nodes

- **Location**: `feature/home/HomeScreen.kt` (statement card)
- **Category**: Accessibility
- **Impact**: TalkBack reads "ALL SETTLED", then "₱0.00", then "0 recent outings · 4 adults" as
  separate stops, so the headline loses its number.
- **Recommendation**: Merge with `Modifier.semantics(mergeDescendants = true) { contentDescription = "All settled, zero pesos, 0 recent outings" }`.
- **Suggested command**: `/impeccable polish`

### [P3] Peso formatting depends on the device locale

- **Location**: `core/money/Money.kt:formatPeso`
- **Category**: Hardening
- **Impact**: `"%,d.%02d".format(...)` uses the default locale; on a device set to a locale with
  different grouping, the recap and the ledger could disagree with the receipt.
- **Recommendation**: Format with an explicit `Locale("en", "PH")` (or `NumberFormat` pinned to it)
  so the peso string is stable everywhere, including the recap image renderer.
- **Suggested command**: `/impeccable harden`

## Patterns & Systemic Issues

- **Lists are built per screen, not per architecture.** Only Students uses `LazyColumn`; History,
  Home, Ledger, and Settings all use `verticalScroll` columns. This is fine for Settings and Home's
  five rows, and wrong for History and payment history.
- **State labels are hand-written per screen.** "LOCAL LEDGER" and the backup status block are
  independent strings computed from different sources; there is no single status model rendered
  once.
- **Copy lives in code.** Zero string resources means pluralization, localization, and TalkBack
  phrasing all have to be fixed in `Text(...)` calls.

## Positive Findings

- **Money correctness is visibly real.** Integer centavos throughout, 19 unit tests, and a device run
  where ₱825.00 split to ₱451.00 / ₱308.00 / ₱33.00 / ₱33.00 exactly.
- **Theming is textbook.** No hard-coded colors outside the theme (the only `Color.rgb` calls are in
  the PNG recap renderer, which is intentional). Dynamic color on Android 12+ with a complete static
  fallback and a real dark scheme.
- **Material conformance.** Components, shapes, and motion are all Material 3; no imported iOS
  patterns; system Back untouched.
- **Labels are done where they matter.** Every icon-only `IconButton` carries a `contentDescription`;
  the `null` descriptions are on decorative icons inside already-labeled buttons, which is correct.
- **Fast start.** 416 ms to first frame on hardware, with Room and Hilt initialised.
- **Empty states everywhere.** Every list has a purposeful empty state with an action, not a blank
  screen.
- **Privacy is visible in the UI**, not just the code: the backup block states what stays local.
